# AS5600接入完整控制器

2026-10-24。当前实际主控仍为ESP32-S3 N16R8，通过CH343的COM4通信。ESP32-C3只作为后续方向，GPIO15不能直接沿用到常见C3板。

版本：`v0.2.0`。本次已编译并烧录完整控制器环境；板上角度自检通过，144帧状态全部磁场有效，静止RAW3207，约281.87°。初始未校准、档位--。PC端24项测试通过，原电位器环境编译通过。打开校准窗口后用户反馈“完美”，确认接入效果正常；实际保存的15点表、逐档游戏验证和双向回差复测尚未单独读回记录。

| 接口 | 当前接线 |
| --- | --- |
| AS5600 SDA / SCL | GPIO7 / GPIO15 |
| AS5600 VCC / GND / DIR | 3V3 / GND / GND |
| AS5600 OUT / GPO | 外部留空 |
| MAX7219 DIN / CS / CLK | GPIO6 / GPIO5 / GPIO4，沿用现有供电和电平转换 |
| 换向前进按钮 | GPIO10对地，内部上拉 |

## 使用

1. 关闭独立“AS5600实时角度”窗口，释放COM4。
2. 上传 `s3_as5600_controller`，启动 `test_tools/启动AS5600控制器.cmd`，选择COM4并连接。
3. 确认实时角度正常、没有磁铁/通信异常。新传感器没有校准时CAL0、档位--，点阵显示横线。
4. 点击开始校准，依次停稳于EB、B8～B1、N、P1～P5，逐个采集，再校验并保存。相邻卡位至少12个角度计数，约1.05°；实际区分度和机械重复性仍需逐档验证。
5. 保存时软件自动选择展开起点，将0°跳变放在未使用的角度间隙中。支持正反方向，以及有效行程跨0°的情况；乱序、重复或间隔过小会拒绝保存。重新校准失败不会覆盖已保存的有效数据。
6. 保存后自动读回校准表。屏幕角度来自原始绝对角度，POS及保存的中心表是软件展开坐标，两者数值不同是正常的。采集期间表中先显示原始角度计数，保存后刷新为展开值。
7. 检查全部档位和点阵，再创建虚拟手柄、启动游戏，物理N后手动启用输出。GPIO10选择前进F；仍使用同一XInput手柄X轴保持换向、Y轴输出档位。

```powershell
python -m platformio run -d firmware -e s3_as5600_controller -t upload --upload-port COM4
python test_tools/serial_notch_bridge.py
```

## 校准与故障处理

- 使用独立NVS命名空间 `jr-as56` 和新格式标记，不读取电位器校准，也不覆盖电位器的 `jr-m3` 数据；需要实测重新采集。
- CAP对角度做圆周均值，EMA同样处理跨0°，避免359°与1°被平均到180°。
- 启动时运行角度算法自检：正反方向跨零、重复卡位、乱序和越界数据。
- 每次读取检查I2C应答与磁铁MD/ML/MH状态。读失败或磁场异常时不输出有效档位；短暂错误也至少上报一次故障，PC复位双轴并停用，恢复后需要手动启用。
- 不写AS5600配置寄存器或OTP。磁铁、轴或模块安装位置调整后应重新校准。
- 原 `s3_uart` 电位器环境与独立 `s3_as5600_test` 角度测试环境继续保留。当前尚未声称第二版游戏验收完成。
