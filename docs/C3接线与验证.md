# ESP32-C3 载板验证

2026-11-01，实物识别为 ESP32-C3 revision v0.4、4MB Flash，USB Serial/JTAG 串口 COM7。用户确认以下接线和换向方向。

| 外设 | C3 连接 |
| --- | --- |
| MAX7219 DIN / CS / CLK | GPIO4 / GPIO3 / GPIO2 |
| AS5600 SDA / SCL / DIR | GPIO6 / GPIO5 / GND |
| 点阵、AS5600 供电 | 3V3，共地；用户已确认该点阵可用 3V3 |
| 三档开关 F / 公共端 / R | GPIO7 / GND / GPIO1；中间断开为 N |
| 按钮 1～4 | GPIO0、10、20、21，另一端 GND |

固件默认环境为 `c3_as5600_controller`，保留 S3 原环境。C3 使用原生 USB Serial/JTAG 通信，不使用 GPIO20/21 的 UART0 作为应用串口。不要将 S3 的 GPIO15 接线或 S3 固件直接用于 C3。

```powershell
pio run -d firmware -e c3_as5600_controller -t upload --upload-port COM7
python test_tools/serial_notch_bridge.py
```

启动 `test_tools/启动AS5600控制器.cmd`，选实际串口并连接。窗口自动识别 C3，显示角度、档位、物理换向和四个按钮的 0/1 状态。GPIO0/10/20/21 依次映射手柄 A/B/X/Y，按住保持、松开释放，支持同时按下；需手动启用输出才会发送，停止、断线、超时或校准时释放全部按钮。旧独立角度窗口仅适用于 S3 测试固件，此处使用完整控制器窗口。

新板需要重新采集 EB、B8～B1、N、P1～P5 共 15 点并保存。未校准时 CAL0、档位 --、点阵横线是正常状态。点阵保留牵引数字、制动数字加右下角灯、N/E 的规则。

换向触点与按钮使用内部上拉、30ms 消抖。开关两侧同时接地上报 X，桥接停用并复位双轴。启用输出前，主手柄和换向开关都置 N；启用后在主手柄 N 时拨到 F 或 R。其他档位期间的换向变化会被消耗，回 N 后需要重新拨动开关，不补发旧动作。F/N/R 对应 XInput LX +32767/0/-32767；R 的游戏实际效果仍需观察 HUD 验证。

超时、重启、传感器异常或校准失效继续停用输出，需手动重新启用。先创建虚拟手柄，再启动游戏。

软件检查：32 项协议、换向及 XInput 测试通过；C3 固件编译通过。实际烧录与传感器读取结果见后续验证记录。

## 换向器校准与按钮更新

新版已烧录，32 项软件测试通过，覆盖全部 16 种 A/B/X/Y 组合、按键释放、轴保持和停止输出复位。C3、S3 AS5600 固件编译通过。实机验证 RBEGIN 后上报 X、重复采集同一触点时 RSAVE 拒绝、RCANCEL 恢复旧映射，随后 50 帧传感器状态全部有效。新版窗口已连接 COM7，仅监看。

1. 在“换向器校准”点击“开始换向校准”，游戏输出停止。
2. 开关拨到你希望的物理前进位置，停稳，目标 F 时点击“采集当前位置”。
3. 拨到中间空挡，目标自动变为 N，再采集。
4. 拨到物理后退位置，目标 R 时采集，再点击“保存换向校准”。
5. 结果保存在板上独立命名空间 `jr-rev`，断电保留，不覆盖主手柄的 15 点校准。两端可反接，软件按学习结果解释；中间必须断开。取消或无效保存保留旧映射。
6. 校准后主手柄与开关都置 N，再手动启用输出。按钮仅对应标准手柄 A/B/X/Y，游戏内各自用途由游戏设置决定。

串口命令：`RBEGIN`、`RCAP F`、`RCAP N`、`RCAP R`、`RSAVE`、`RCANCEL`、`RDUMP`。实际拨动三档并保存、断电读回、实体按钮在游戏中的响应仍待用户验证；本次未代替用户采集物理位置。

## 四按钮校准与新版界面（0.3.1）

进入“校准与设置 → 按钮”，点击开始。按住希望用作 A 的实体按钮并采集，再分别采集 B、X、Y，最后保存。四个实体输入可任意排序，每个只能分配一次；空按、多按、重复和未采集齐都会拒绝。保存到独立 NVS `jr-btn`，不覆盖角度或换向校准。取消保留旧映射，关闭校准窗口自动取消未保存内容并恢复连接。

默认映射仍为 GPIO0/10/20/21 → A/B/X/Y。串口命令：`KBEGIN`、`KCAP A`（或 B/X/Y）、`KSAVE`、`KCANCEL`、`KDUMP`。
