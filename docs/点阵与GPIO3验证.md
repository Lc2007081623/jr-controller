# 2026-10-21：MAX7219点阵与GPIO3电位器

本次替代临时OLED方案，沿用已验证的 `firmware/src/matrix_scroll.cpp` 点阵驱动参数。独立数字循环测试程序保留。

| 接口 | ESP32-S3 |
| --- | --- |
| 电位器滑动端 | GPIO3 |
| 电位器两端 | 3V3 / GND，沿用已有分压、限幅与滤波接线 |
| MAX7219 DIN | GPIO6 |
| MAX7219 CS | GPIO5 |

电位器滑动端从原GPIO5移到GPIO3，GPIO5现在输出点阵CS信号。OLED不再连接或驱动。GPIO3表示板上标注的IO3，不是排针第三个位置。

## 点阵显示

| 本地档位/状态 | 画面 |
| --- | --- |
| P1～P5 | 单个数字1～5，右下角灭 |
| B1～B8 | 单个数字1～8，最右下角LED亮 |
| N | N，右下角灭 |
| EB | E，右下角灭 |
| 未校准 | 横线 |
| 正在校准 | C |

数字沿用刚验证程序的5×7字模、亮度2、旋转0、无镜像。制动标记独占第8行第8列。显示的是物理手柄识别档位，游戏输出是否启用由PC窗口决定。MAX7219没有读回，窗口“显示配置”只报告引脚配置，不宣称检测到硬件。

## 重新验证

1. 编译/上传环境使用 `s3_uart`，当前串口COM4，115200波特。
2. 启动 `test_tools/启动第一版验证.cmd`，选择COM4并连接；先转动电位器，检查RAW/ADC变化。
3. 点击开始校准，逐档停稳并采集：EB、B8～B1、N、P1～P5，然后校验保存。
4. GPIO3版使用独立NVS命名空间 `jr-m3`，不会沿用GPIO5版的旧校准。保存后重启可保留；重新开始校准失败不会覆盖已保存数据。
5. 拨动每档检查：P与B同数字时，只有B点亮右下角。N/E也应清除制动标记。物理方向需实看确认。
6. 校准完成后再创建虚拟手柄、启动游戏，物理置N后手动启用输出。默认只监看；断线超过500ms置N并停用输出。

## GPIO10：换向器前进请求

2026-10-21新增：30ms消抖，按下计数通过串口上报。窗口显示“按钮10”：松开0、按下1。按住不连发，上电已按住、重新连接、积压旧事件与重启都不补发。

PC改用同一个虚拟Xbox手柄：左摇杆Y轴继续输出档位；GPIO10在已启用输出、物理N时选择F，X轴锁存为+32767，不因松开按钮或切换P/B档清零。停止输出、断线超时、校准和窗口关闭时回到X=0、Y=0。初始状态是N，不会在重连时补发按钮。窗口显示的是换向请求，不是游戏遥测。

此前键盘↑脉冲方案已停用。`reverser_key.py`仅保留为历史诊断代码，当前桥接不导入、不发送键盘输入，也不再要求游戏前台才记录GPIO10的XInput换向请求。正常操作仍应在驾驶画面、列车静止时验证HUD。

验证顺序：连接COM4 → 确认CAL1 → 创建虚拟手柄 → 再启动/重启游戏 → 物理N并启用输出 → 切回游戏、列车静止时按GPIO10按钮，观察换向器HUD → 再检查牵引/制动档位。若始终显示monitor only，电位器不会输出游戏档位。无需重新采集电位器校准。

实际采集发现EB=1435、B8=1419，间隔16。当前校准要求严格单调、相邻至少12、总跨度至少500，保留迟滞；EB/B8的迟滞为3计数。此前25计数门限已调整。应重点实测EB/B8在各卡位上是否稳定，软件校验通过不代替卡位抖动验证。

测量数据备份保存在本机 `hardware_backups/calibration_20261021_adc3.json`。维护恢复协议为 `BEGIN`、逐条 `SET 档位 ADC值`、`SAVE`；SET只在校准中可用，不直接写入NVS，SAVE仍检查全部15点。不应拿估计值替代实际测量。

2026-10-21验证记录：调整门限后已恢复并保存本次全部15点。CH343 RTS重启后，启动标识变化、校准有效，DUMP读回15个值与备份逐项一致；当时ADC1339，识别B7。越界SET及含多余参数SET均被设备拒绝。EB/B8稳定性、点阵物理显示与全部游戏档位仍需用户逐档确认。
