# ESP32-S3单手柄控制器：技术总结

记录日期：2026-10-14。当前验证车型：JR EAST Train Simulator，中央线E233系0番台。

## 核心结论

可以通过软件提供绝对档位输入。电脑端创建虚拟Xbox 360手柄，向左摇杆Y输出每档的稳定值，游戏原生XInput分支将其转换为牵引和制动目标档位。本次已实际验证P1、P3、B5直接命中，不依赖Steam Input，也不使用键盘多次增减。

S3普通USB HID Gamepad与Windows XInput是不同接口。本项目采用S3 USB串口加PC虚拟XInput桥接。2026-10-19新增第一版采样固件、串口桥接与15点校准窗口，已通过编译和PC协议测试，完整实物链路待验证。2026-10-21进一步改为ADC GPIO3与MAX7219（DIN6、CS5、CLK4），已烧录并读取状态，操作见[点阵与GPIO3验证](点阵与GPIO3验证.md)。此前手动测试程序已验证后半段链路。

## 接口分析方法

使用PE导入表、字符串交叉引用、Windows x64指令反汇编和随附操作说明，定位了XInput读取函数与档位转换函数。没有修改游戏、写入进程内存或注入DLL。

观察到的主要逻辑：

1. 初始化时扫描XInput用户槽0–3；找到控制器后切换至XInput输入类型。
2. 驾驶输入分派受输入类型、操作模式和车型条件控制。
3. 绝对输入分支读取左摇杆X/Y，将有符号16位值除以32767。
4. 左摇杆Y与内部阈值表比较，产生目标牵引/制动数值。
5. 目标与当前状态不同才更新对应状态，不依赖连续“加档/减档”按键。
6. 可读取外部`knotch2.ini`及特殊车型配置；普通配置缺失时使用内置阈值。

因此这里的“接口”是原生XInput输入入口，未发现可供外部随意调用的通用`SetNotch`公共API。串口和CONTEC也有代码线索，但其协议与启用方式没有确认。

参考：[Microsoft XINPUT_GAMEPAD结构](https://learn.microsoft.com/en-us/windows/win32/api/xinput/ns-xinput-xinput_gamepad)。

## 实测过程

| 阶段 | 结果 |
| --- | --- |
| 创建虚拟手柄 | 成功；使用用户安装的ViGEmBus及vgamepad |
| Windows XInput读回 | 槽0连续8次读回LX=0、LY=655，与中立区测试输出一致 |
| 先开游戏、后创建虚拟手柄 | HUD无变化；只读输入类型值为3 |
| 保持虚拟手柄开启并重启游戏 | 驾驶中读到输入类型4、操作模式值8 |
| P1 → P3 → B5 | 用户观察HUD确认三个目标全部直接对应 |

结论：启动顺序是当前实现的一部分。输入类型/操作模式值为内部数值，含义由该版本分派逻辑推导；不是建议用户直接改配置或内存。

当前成功仅覆盖已测试的三档和E233 0番台。拔插恢复、其他档位、菜单、其他车型及硬件电位器都仍需验证。

## S3与硬件规划

已有检查记录确认主控为ESP32-S3，外部Flash检测16MB，芯片报告内置8MB PSRAM。容量识别不是完整内存自检，也不能凭芯片信息锁定板卡修订和排针封装。

电位器选型更新（2026-10-18）：用户决定先用低成本 RK097N B10K 三脚款，按10kΩ单联线性输入设计。依据是用户提供的商品截图，并非 ALPS 原厂型号；到货后确认线性、端子、是否带定位及机械行程。原 RK09L1120A5F 保留为备选。机械卡位、转轴承力和限位由机构承担，电位器只测位置。

A1图纸沿用A0电路参数：3.3V经4.7kΩ接电位器上端，另一端接地，滑动端经1kΩ至GPIO1，ADC节点100nF到地。标称上端约2.24V，实际电压、ADC范围和有效机械行程需测量。

模拟采样链路应为：实际ADC中心值校准 → 短窗口滤波 → 阈值迟滞/防抖 → 物理档位 → 查表输出游戏轴值。物理档位校准表与游戏轴值表是两张独立表。

现有按钮、换向、独立EB及MAX7219电路可以继续使用。点阵显示本地物理档位，不是游戏实际档位的遥测。

硬件依据：[Espressif S3 USB设备栈](https://docs.espressif.com/projects/esp-usb/en/latest/esp32s3/usb_device.html)、[原备选ALPS型号资料](https://tech.alpsalpine.com/e/products/detail/RK09L1120A5F/)、[SN74AHCT125](https://www.ti.com/lit/ds/symlink/sn74ahct125.pdf)、[MAX7219](https://www.analog.com/media/en/technical-documentation/data-sheets/MAX7219-MAX7221.pdf)。

## 下一阶段实现

1. S3固件先仅输出原始ADC与稳 定物理档位，完成实际卡位校准；只在校准确认时保存NVS。
2. 设计带版本号、序号和当前档位的串口状态报文，重连时完整上报，PC检查合法范围与超时。
3. 将现有手动XInput测试后端接上串口读取。通信恢复需明确同步；断线策略需与游戏实测一起决定。
4. 验证全部P/B/EB、跨档、快速往返、暂停/菜单、启动顺序及拔插。
5. 再加入按钮与显示。警笛等保持型按钮与一次性动作要保留正确按下/释放语义。

目前没有烧录固件、生产PCB或完成整机装配。公开文件是工程规划、手动测试程序与阶段性验证记录。
