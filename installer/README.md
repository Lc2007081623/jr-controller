# Windows 简化安装包

当前版本 0.4.0：正式集成已获用户实测确认的 ZUIKI PRO 换向器映射（33DD:0006，Rz：F=128 / N=0 / R=255）。两个游戏模式均不再要求回 N 才启用，换向器在任意主手柄档位实时跟随。连接或恢复时会立即输出实体当前位置，包括已有牵引、制动和按下的按钮。仍要求传感器正常、校准有效；断线、数据过期、异常触点和校准期间释放输出。新界面使用深色标题栏、等宽仪表卡与 F/N/R 高亮。底层 ViGEmBus 保持 1.22.0；更新的是控制器程序与安装包。63 项测试通过。

0.4.0 打包验证：EXE 已连接 COM7，在 B3 档直接进入就绪；切换 RUNNING TRAIN 后 Windows 枚举 `VID_33DD&PID_0006`。主窗口在本机 150% 缩放下完整显示。用户此前确认的 Pro 映射已复用，新版本取消软件限制后的游戏内部联锁行为仍由游戏决定。无驱动全新电脑首次安装尚未复测。

0.3.2：已集成 RUNNING TRAIN（ZUIKI）模式。在主窗口“游戏模式”选择它，再启动或重启 RUNNING TRAIN，并关闭该游戏的 Steam Input。主手柄和四按钮使用此前验证的 ZUIKI 输出；换向器待解决，暂不向游戏发送方向操作。切换会释放并移除旧虚拟设备、重新等待回 N；选择保存到本机，下次自动恢复。校准数据不受模式切换影响。56 项测试通过。

目标为 Windows 10/11 x64。`release/JRControllerSetup.exe` 内含 Python 运行环境、控制器程序与官方 ViGEmBus 1.22.0 安装程序；目标电脑不需要安装 Python、pip 或单独下载驱动。首次安装需要管理员授权，驱动要求重启时安装器提示重启。

点击安装后自动检查 ViGEmBus，已有驱动则跳过；创建桌面和开始菜单入口，默认写入登录启动项。后台以最小化窗口运行，退出程序会释放全部输入。卸载只移除本程序，保留可能被其他软件使用的 ViGEmBus 驱动，驱动可从 Windows 已安装应用中单独卸载。被系统占用的卸载文件会在重启时清理。

校准数据仍在 C3 板上。插入后自动识别原生 USB 串口，有效数据到达后立即输出当前档位、方向和按钮。断开、超时或传感器错误会释放全部输入；恢复后自动跟随当前位置。虚拟手柄在程序启动时创建，建议让程序随登录启动、然后启动游戏。若游戏先启动且未识别，或切换了虚拟设备身份，需要重启游戏。RUNNING TRAIN 需关闭 Steam Input。

打开“校准”暂停游戏输出，沿用完整的主手柄 15 点及换向器校准界面，关闭校准窗口后自动恢复连接。不再需要手动选择 COM、创建手柄或启用输出。

0.3.1 更新：主窗口使用浅色卡片显示档位、方向和按键亮起状态；“校准与设置”内按页签选择主手柄、换向器或按钮。按钮页可以将四个实体按钮重新指定为 A/B/X/Y，保存到 C3，断电保留。RUNNING TRAIN 换向器问题保持待解决，其独立 ZUIKI 试验脚本未并入本安装包。

0.3.1 最终验证：52 项测试通过；修复旧实例锁权限导致的 WinError 5。打包 EXE 首次启动正常，重复打开会恢复已有窗口并正常退出。用户学习的四按钮映射已经在开发板硬复位后读回确认，高分屏下主界面与四行按钮表布局已调整。

构建：安装 `test_tools/requirements.txt` 及 PyInstaller 6.16.0（设置 `VGAMEPAD_SKIP_VIGEMBUS_INSTALL=true`，仅安装 Python 依赖）。准备官方 `ViGEmBus_1.22.0_x64_x86_arm64.exe` 和源仓库 `LICENSE` 至 `.local-tools/installer/`（许可证文件名 `ViGEmBus-LICENSE.txt`），再执行 `python installer/build.py`。程序与安装器都用 PyInstaller 打包，安装器使用 Python 标准库，不需要额外安装编译器。构建会核对已验签驱动的固定 SHA256。

驱动来源：https://github.com/nefarius/ViGEmBus/releases/tag/v1.22.0

驱动安装器保持官方签名；外层 JR 安装包尚未代码签名。免 Python 打包不等于已在无驱动的另一台电脑验收，首次安装与重启路径需另机验证。

本机验证：40 项软件测试通过，包含自动启用、超时、重启、异常触点、按钮释放和安装器边界检查。独立打包程序已启动，自动读取 COM7 与 C3 板上已保存的校准；校准入口可打开，关闭后恢复监看。安装包的 x64／管理员清单与运行环境、客户端 DLL、官方驱动和许可证载荷均已检查。未在本机重复安装驱动，也未改写现有校准。

同一 Backend 的实机 XInput API 回读验证通过：15 个档位、F/N/R、全部 16 种 A/B/X/Y 组合，以及最终双轴归零、按钮释放。检测发现虚拟手柄刚创建时本机初帧为 X=-3356/Y=-1869，首次主档位变化后恢复准确回读，随后 N 为 0/0；未为消除此现象而在启动时发送牵引指令。新电脑首次安装、游戏内启动状态与兼容性仍需验证。
