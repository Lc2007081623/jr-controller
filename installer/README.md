# Windows 简化安装包

## 当前完整安装包 1.1.5

Hidari 2 连接后，可在「设定 → 模型驾驶」读取和保存 Odoriko 参数。内置固件 1.2.5 支持最低输出电压设定和 0–12 V 输出电压仪表。

选择 JR EAST（Xbox）模式后，主界面的「启动 JR EAST」可记住 Steam 或游戏 EXE 入口，等控制器输出就绪再启动。安装窗口提示安装前退出 360 等杀毒软件，完成后重新开启。

本版加入主题、更新查询、各游戏接入说明、本机 HTTP 接口与配套 C3 点阵固件更新。构建需安装 PlatformIO，并提供 Espressif esptool 5.3.0 的 Windows 工具目录，可通过 `JR_ESPTOOL_DIR` 指定。实物刷写与点阵显示尚待验证。

新增 TRAIN CREW（官方接口）模式：游戏输入设置启用外部输入/输出，直接输出主手柄、换向和四按钮；安装包内置官方SDK和.NET桥接程序，不需另配虚拟手柄。B7/B8映射到游戏B6常用最大。详情见 `train_crew_guide.html`。

BVE 5/6 已集成专用插件：可选游戏目录，留空时插件仅放在安装目录的 `BVE Plugins/BVE5`、`BVE Plugins/BVE6` 中，随后按离线说明手动复制。BVE 游戏需自行安装并在 Input device 设置中启用 JR Controller。

给新用户的唯一安装文件是 `release/JRControllerSetup.exe`，约 42 MB。不需要提供 Python、pip、vgamepad 或单独的 DLL。支持 Windows 10/11 Intel/AMD 64 位，硬件按已烧录配套固件的 C3 成品处理；游戏本身由用户安装。

使用顺序：退出游戏与旧 JR 控制器 → 双击安装包并同意管理员授权 → 点击“一键安装” → 可选填 BVE 5/6 游戏目录 → 等待驱动安装、程序及插件复制和四个输出模式自检 → 如提示则重启电脑 → 从桌面打开 JR Controller → USB 连接硬件 → 选择游戏模式 → 启动游戏。RUNNING TRAIN 关闭 Steam Input。校准或故障处理可在程序中点击“使用说明”，无需联网。

安装器用离线官方驱动载荷安装或修复，服务存在时也会实际检查虚拟设备创建。重启返回码会进入“待重启”状态，不宣称自检通过；不自动重启电脑。安装错误记录在 `C:\ProgramData\JRController\setup.log`，可点“查看安装日志”。“安装通过”不等于游戏识别通过，需进入游戏确认 HUD。

84 项测试覆盖缺少驱动、已有驱动修复、需要重启、进程自检报告与设备释放等分支。外层安装包尚未代码签名；无驱动全新电脑的实际安装和重启仍需另机验收，本机自检不能替代这个验收。

已对打包 EXE 的 `--self-check` 入口实测，返回码 0，Xbox、Pro、BVE、TRAIN CREW 四项通过；不需要连接硬件或调用本机 Python。内置驱动官方签名有效。官方 1.22.0 EXE 是 Advanced Installer 引导程序，静默安装采用 `/exenoui /qn /norestart`，修复采用 MSI `/fomus //`；参数依据 [引导程序文档](https://docs.advancedinstaller.com/exe-setup-file.html)。

## 多型号固件（1.1.3 起）

每款板在 `firmware/platformio.ini` 有独立的构建环境，分别维护 `custom_firmware_series`、`custom_firmware_model` 和 `custom_firmware_version`。现有两个构建目标为 `hidari1`（`JR-C3-AS5600-R1`）和 `hidari2`（`JR-C3-HIDARI-2`）。单款固件更新时，只提高该环境的版本。

安装器构建会生成 `hidari<编号>-v<版本>-app.bin` 和 `manifest.json`。更新器按设备上报的型号查清单，并核对设备编号、应用分区和 SHA-256。无型号的旧固件需要先确认实物型号，再用对应的 PlatformIO 环境烧录；这个 `.bin` 是应用区更新镜像。

## 以前版本与开发验证记录

历史版本 0.4.0：正式集成已获用户实测确认的 ZUIKI PRO 换向器映射（33DD:0006，Rz：F=128 / N=0 / R=255）。两个游戏模式均不再要求回 N 才启用，换向器在任意主手柄档位实时跟随。连接或恢复时会立即输出实体当前位置，包括已有牵引、制动和按下的按钮。仍要求传感器正常、校准有效；断线、数据过期、异常触点和校准期间释放输出。新界面使用深色标题栏、等宽仪表卡与 F/N/R 高亮。底层 ViGEmBus 保持 1.22.0；更新的是控制器程序与安装包。63 项测试通过。

0.4.0 打包验证：EXE 已连接 COM7，在 B3 档直接进入就绪；切换 RUNNING TRAIN 后 Windows 枚举 `VID_33DD&PID_0006`。主窗口在本机 150% 缩放下完整显示。用户此前确认的 Pro 映射已复用，新版本取消软件限制后的游戏内部联锁行为仍由游戏决定。无驱动全新电脑首次安装尚未复测。

0.3.2：已集成 RUNNING TRAIN（ZUIKI）模式。在主窗口“游戏模式”选择它，再启动或重启 RUNNING TRAIN，并关闭该游戏的 Steam Input。主手柄和四按钮使用此前验证的 ZUIKI 输出；换向器待解决，暂不向游戏发送方向操作。切换会释放并移除旧虚拟设备、重新等待回 N；选择保存到本机，下次自动恢复。校准数据不受模式切换影响。56 项测试通过。

目标为 Windows 10/11 x64。`release/JRControllerSetup.exe` 内含 Python 运行环境、控制器程序与官方 ViGEmBus 1.22.0 安装程序；目标电脑不需要安装 Python、pip 或单独下载驱动。首次安装需要管理员授权，驱动要求重启时安装器提示重启。

点击安装后自动检查 ViGEmBus，已有驱动则跳过；创建桌面和开始菜单入口，默认写入登录启动项。后台以最小化窗口运行，退出程序会释放全部输入。卸载只移除本程序，保留可能被其他软件使用的 ViGEmBus 驱动，驱动可从 Windows 已安装应用中单独卸载。被系统占用的卸载文件会在重启时清理。

校准数据仍在 C3 板上。插入后自动识别原生 USB 串口，有效数据到达后立即输出当前档位、方向和按钮。断开、超时或传感器错误会释放全部输入；恢复后自动跟随当前位置。虚拟手柄在程序启动时创建，建议让程序随登录启动、然后启动游戏。若游戏先启动且未识别，或切换了虚拟设备身份，需要重启游戏。RUNNING TRAIN 需关闭 Steam Input。

打开“校准”暂停游戏输出，沿用完整的主手柄 15 点及换向器校准界面，关闭校准窗口后自动恢复连接。不再需要手动选择 COM、创建手柄或启用输出。

0.3.1 更新：主窗口使用浅色卡片显示档位、方向和按键亮起状态；“校准与设置”内按页签选择主手柄、换向器或按钮。按钮页可以将四个实体按钮重新指定为 A/B/X/Y，保存到 C3，断电保留。RUNNING TRAIN 换向器问题保持待解决，其独立 ZUIKI 试验脚本未并入本安装包。

0.3.1 最终验证：52 项测试通过；修复旧实例锁权限导致的 WinError 5。打包 EXE 首次启动正常，重复打开会恢复已有窗口并正常退出。用户学习的四按钮映射已经在开发板硬复位后读回确认，高分屏下主界面与四行按钮表布局已调整。

构建：安装 `test_tools/requirements.txt` 及 PyInstaller 6.16.0（设置 `VGAMEPAD_SKIP_VIGEMBUS_INSTALL=true`，仅安装 Python 依赖）。准备官方 `ViGEmBus_1.22.0_x64_x86_arm64.exe` 和源仓库 `LICENSE` 至 `.local-tools/installer/`（许可证文件名 `ViGEmBus-LICENSE.txt`），再执行 `python installer/build.py`。程序与安装器都用 PyInstaller 打包，安装器使用 Python 标准库，不需要额外安装编译器。构建会核对已验签驱动的固定 SHA256。

驱动来源：https://github.com/nefarius/ViGEmBus/releases/tag/v1.22.0

驱动安装器保持官方签名；外层 JR 安装包尚未代码签名。免 Python 打包不等于已在无驱动的另一台电脑验收，首次安装与重启路径需另机验证。

本机验证：40 项软件测试通过，包含自动启用、超时、重启、异常触点、按钮释放和安装器边界检查。独立打包程序已启动，自动读取 COM7 与 C3 板上已保存的校准；校准入口可打开，关闭后恢复监看。安装包的 x64／管理员清单与运行环境、客户端 DLL、官方驱动和许可证载荷均已检查。未在本机重复安装驱动，也未改写现有校准。

同一 Backend 的实机 XInput API 回读验证通过：15 个档位、F/N/R、全部 16 种 A/B/X/Y 组合，以及最终双轴归零、按钮释放。检测发现虚拟手柄刚创建时本机初帧为 X=-3356/Y=-1869，首次主档位变化后恢复准确回读，随后 N 为 0/0；未为消除此现象而在启动时发送牵引指令。新电脑首次安装、游戏内启动状态与兼容性仍需验证。
