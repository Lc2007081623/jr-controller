# JR 绝对档位测试

适用当前静态分析的普通单手柄分支，首个验证车型为中央线 E233 系 0 番台。

## 启动顺序

1. 双击 `启动档位测试.cmd`。窗口会创建虚拟 Xbox 360 手柄，初始输出 N。
2. 点“查看 XInput 槽”，确认至少有一个槽；真实 Xbox 手柄如果占用较低槽，先正常断开它。
3. 保持测试程序开启，再启动游戏。已找到游戏初始化中的 XInput 检测，游戏启动之后才建立虚拟手柄可能不会切换输入模式。
4. 进入驾驶画面，先选 N，再逐项测试 P1、P3、B1、B5。按钮点击后默认延迟 3 秒，期间切回游戏，程序持续保持该绝对 Y 值。
5. 以游戏 HUD 实际档位为准，记录是否直接命中。EB、P5 只在基本档位验证后按需要手动测试。
6. 暂停/结束测试时点“取消排队并立即输出 N”；关闭窗口会重置并移除本测试虚拟手柄。

虚拟手柄驱动为用户已安装的 ViGEmBus；本目录仅安装了 vgamepad Python 库，安装时关闭了自动驱动安装。测试程序不修改游戏、Steam 配置或内存。

## 当前实际结果

**游戏端已通过用户实测：重启后 P1 → P3 → B5 三个档位均直接对应，车型为中央线 E233 系 0 番台。**

第一次测试未变化，当时游戏输入类型=3。保持虚拟手柄开启后重启游戏，进入驾驶后读到布局=8、输入类型=4、车型选择字段=0，随后用户确认三个目标档位全部对应。此次结论仅覆盖该车型和这三个采样档位，其余档位、特殊车型与物理电位器尚未实测。

- 15 档输出值、XInput 结构大小已通过程序检查。
- 已成功创建虚拟手柄；Windows XInput 槽 0 连续 8 次读回 LX=0、LY=655，与发出的中立区测试值完全一致。
- 首次游戏运行中的输入选择值：布局=8、输入类型=3、车型选择字段=0。
- 绝对 XInput 分派要求输入类型=4，故上述状态不能证明游戏已启用绝对轴输入。
- 静态初始化代码 0x1400b70ef 调用 XInput 检测；有控制器时 0x1400b70fe 将输入类型写为4。已经通过“先启动测试窗口，再启动游戏”完成验证。
- 游戏 HUD 的 P1、P3、B5 结果已由用户确认。软件发送/Windows 读回日志保存在 test_events.jsonl，不应把该日志单独当作 HUD 证据。

## 诊断

`python xinput_notch_test.py --slots`：读取 Windows 当前 XInput 状态。

`python xinput_notch_test.py --self-test`：检查结构与输出数值，不运行游戏测试。

`python game_input_probe.py`：只读检查当前游戏进程中的已分析输入选择字段；不写内存。地址仅适用于本次分析的 EXE。

`test_events.jsonl`：程序发送的档位/Y 值和 Windows XInput 读回记录。它不是游戏 HUD 结果。

窗口内“连接失败”或没有 XInput 槽时，应先检查驱动和设备状态。该机 Windows WMI 查询发生过阻塞，程序在导入 vgamepad 时使用已知 OS/指针宽度避开 WMI；不依赖 WMI 判断游戏进程。
